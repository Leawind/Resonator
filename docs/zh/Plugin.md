# 插件

Resonator 使用插件系统来扩展其功能。插件可以是服务端插件或客户端插件，它们通过
Resonator 协议进行通信。

## 总体设计

插件系统的设计围绕两大核心功能：

- 客户端向服务端查询，服务端返回查询结果
- 客户端向服务端订阅事件并指定条件，服务端返回订阅标识，事件触发时推送给相应客户端

### 查询

查询包含的信息：

| 名称           | 解释                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 请求标识       | 当受到请求结果时，客户端需要知道该结果对应的是哪个请求，所以每个请求都有一个标识。请求标识由客户端生成。 |
| 服务端插件标识 |                                                                                                          |
| 插件内方法标识 | 插件可以提供若干查询方法，每个方法在其插件内都有一个唯一标识。                                           |
| 查询参数       | 查询参数应当是一个数组                                                                                   |

方法标识在插件中是唯一的，且不允许类似 java 的重载。

服务端接收到查询请求后，找到对应插件中的方法，插件提供执行该方法的逻辑。处理完成后向客户端发送一个表示结果的消息。

插件的方法不必能够访问其所在的服务端实例。

处理结果包含的信息：

| 名称     | 解释                                   |
| -------- | -------------------------------------- |
| 请求标识 | 请求消息中包含的由客户端生成的请求标识 |
| 查询结果 | 表示查询结果的对象，可以为空           |

### 事件订阅

事件订阅允许客户端订阅服务端的特定事件，当这些事件发生时，服务端会主动向客户端推送相关信息。

### 流程

注意：

- 判断条件时应当使用原始事件信息和处理后的条件对象
- 原始事件信息和条件对象的类型都由插件决定

#### 插件注册

1. 服务端插件在注册事件时要提供的信息：
   - 事件标识
   - 将原始条件数据处理为条件对象的函数
   - 条件判断函数

#### 订阅

1. 客户端发送订阅请求，指定要订阅的事件标识和相关条件
1. 服务端处理订阅请求
   - 如果重复订阅同一事件且条件相同，则返回同一订阅标识，效果与订阅一次相同。
   - 如果有效则创建订阅并返回订阅标识。
   - 将条件数据处理好并记录条件对象，处理方式由插件提供，默认为包含客户端发来的表示条件的原始数据，`byte[]`类型。

订阅包含的信息：

| 名称           | 解释                 |
| -------------- | -------------------- |
| 请求标识       | 客户端生成的请求标识 |
| 服务端插件标识 |                      |
| 事件标识       | 要订阅的事件类型标识 |
| 条件           |                      |

订阅响应包含的信息：

| 名称     | 解释                                 |
| -------- | ------------------------------------ |
| 请求标识 | 客户端生成的请求标识                 |
| 订阅标识 | 服务端分配的订阅标识，可用于取消订阅 |

订阅标识是在服务端实例中全局唯一的

#### 取消订阅

客户端可以通过订阅标识来取消之前的订阅。取消订阅后，服务端将不再向该客户端推送相关事件。

取消订阅包含的信息：

| 名称     | 解释                 |
| -------- | -------------------- |
| 请求标识 | 客户端生成的请求标识 |
| 订阅标识 | 要取消的订阅标识     |

#### 触发和推送事件

1. 服务端插件在事件触发时构建自定义类型的事件数据（原始事件信息）
1. 服务端插件告诉服务端事件标识和原始事件信息
1. 服务端遍历该事件的所有订阅，使用服务端插件在注册时提供的函数判断客户端的条件是否与原始事件数据相符合
1. 如果存在任意客户端的条件符合，则使用插件的方法序列化事件信息
1. 服务端将事件数据推送给客户端，并告知订阅标识

| 名称     | 解释                                                         |
| -------- | ------------------------------------------------------------ |
| 订阅标识 | 接收事件的订阅标识，客户端插件根据此标识来查找对应的回调函数 |
| 事件数据 | 事件相关的数据，类似于请求参数，应当是一个数组               |

因为订阅标识是跨插件唯一的，所以推送事件时不需要告知插件标识。

## 客户端插件

客户端插件的工作原理是利用客户端实例与服务端通信，插件在实例化时要绑定一个客户端实例。\
用户在使用插件时直接调用插件实例上的方法，因此插件不需要向客户端提供自身的元数据信息。

相应的，客户端实例要为插件提供查询、订阅的方法。

## 服务端插件

服务端需要根据请求中的插件标识找到相应插件，所以插件需要在服务端实例上注册，注册时要提供相应的元数据。

服务端插件需要提供的元数据包括：

- 插件标识
- 可用的查询方法
- 可订阅的事件

此外，服务端实例还要为插件提供触发事件的方法。
